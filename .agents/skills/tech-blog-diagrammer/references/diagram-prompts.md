# 도식 설계와 공식 자료 재사용 기준

## 1. 내용에서 출발하는 설계

그림을 만들기 전에 본문과 1차 출처에서 **노드, 경계, 간선, 방향, 상태와 근거**를 적는다. 각 요소가 어떤 문장을 설명하는지 연결할 수 없다면 넣지 않는다. 요약 카드에 화살표를 붙여 관계가 있는 것처럼 보이게 하지 않는다.

| 설명할 관계 | 권장 형태 | 지켜야 할 조건 |
|---|---|---|
| 요청·데이터 흐름 | 단계와 방향이 있는 흐름도 | 화살표는 실제 통신·데이터 이동에만 쓴다 |
| 대안 비교 | 같은 입력을 공유하는 나란한 구성 | 두 대안을 순차 실행처럼 연결하지 않는다 |
| 상태 변화 | 상태와 전이 조건이 있는 상태도 | 모든 화살표에 출발점·도착점·조건을 둔다 |
| 장애·보안 경계 | 신뢰 영역과 통과 지점이 있는 구성도 | 인증·인가·격리가 자동 보장된다고 암시하지 않는다 |
| 정량 결과 | 측정값·단위가 있는 그래프 | 축·조건·출처가 없으면 그래프를 만들지 않는다 |

한 화면에는 독자가 추적할 수 있는 핵심 요소만 둔다. 장문 설명은 본문에 쓰고, 모델명·버전·수치·레이블은 출처와 대조한다. 모든 글에 같은 3~4장 카드와 장식용 요약 띠를 반복하지 않는다.

### 독립 제작 프롬프트

```text
Create an original technical diagram, not a copy of a reference image.
Question answered: {독자가 이해해야 할 한 가지 질문}
Verified components and boundaries: {검증된 구성 요소와 경계}
Verified edges and directions: {각 간선의 출발점, 도착점, 의미}
Layout: {흐름 / 병렬 비교 / 상태 전이 중 관계에 맞는 형태}
Exact short labels: {오탈자 없이 표시할 최소 라벨 목록}
Do not invent measurements, guarantees, logos, labels, components, or arrows.
Use high contrast, ample whitespace, and legible text at mobile display size.
```

정확한 한글이나 세밀한 선이 중요하면 생성 모델이 그린 글자에 기대지 말고 검증 가능한 벡터 텍스트와 도형으로 만든다. 글자·방향 오류가 남은 결과는 채택하지 않는다.

### 가독성 기준

- 1400px 원본에서 본문 레이블은 최소 16px 상당, 카드 제목은 24px 상당 이상으로 계획하고 실제 390px 화면에서 읽히는지 확인한다.
- 축소 표시 시 읽기 어려운 조밀한 도식은 핵심 부분과 상세 부분을 나누거나 `그림 크게 보기` 링크를 함께 둔다.
- 색 대비는 밝은 배경에 어두운 글자를 기본으로 하고, 색만으로 계열을 구분하지 않는다.
- 화살표가 교차하면 직각 경로와 여백을 우선하고, 선이 글자를 가로지르면 배치를 다시 한다.

## 2. 공식 아키텍처 도식 재사용

공식 문서에서 그림을 찾은 뒤 **그 그림 파일과 변환·재게시 용도**에 적용되는 라이선스를 직접 확인한다. 저장소 코드 라이선스가 이미지에 적용되는지, 제3자 이미지·상표 예외가 있는지 따로 본다.

| 구분 | 판정 | 확인할 근거 |
|---|---|---|
| **허용** | 해당 이미지의 재배포와 필요한 변환을 명시적으로 허용 | CC BY·CC0·퍼블릭 도메인, 또는 이미지에 적용되는 MIT·Apache-2.0·BSD 등의 실제 고지 |
| **조건 확인** | 비상업·변경 금지·동일조건·상표 제약이 있는 자료 | 블로그의 사용 목적과 변환 방식에 맞는지, 별도 허가가 필요한지 확인 |
| **미확인** | 개별 이미지의 권리나 범위가 불명확 | 복제·재게시하지 않고 원문에 링크하거나 별도 독립 도식을 만든다 |

Microsoft Learn의 [이용 약관](https://learn.microsoft.com/en-us/legal/termsofuse)은 별도 허가 없는 웹사이트 이미지의 복사·재전송을 제한한다. 다른 Microsoft 저장소의 CC BY나 [Azure 아이콘 사용 허가](https://learn.microsoft.com/en-us/azure/architecture/icons/#icon-terms)를 기존 문서 그림 전체에 자동 적용하지 않는다.

과거 공개 저장소의 허가본을 근거로 삼으려면 라이선스 고지가 있는 고정 커밋에 그 이미지가 있는지 확인한다. 현행 문서 이미지를 쓸 때는 해당 파일과 허가본을 SHA-256으로 비교한다. 파일명이 같다는 사실만으로 같은 그림이라고 판단하지 않는다.

허가된 공식 도식의 캡션에는 저작자, 원문·허가본 링크, 라이선스 링크와 형식·크기 등 변경 사항을 넣는다. 이미지를 쓰지 못하면 그 이유를 보고한다.
